# Что можно воспроизвести

Публичный репозиторий содержит исходный код, отчёты, 19 проверенных GIF и
самодостаточный численный пример. Полные raw-выгрузки, accepted traces и матрицы
экспериментов хранятся отдельно и не входят в Git.

## 1. Быстрая проверка из чистой копии

Точный научный runtime — **CPython 3.14.7**. Python-код использует стандартную
библиотеку. `uv` управляет выбором версии; эти команды не создают проектное окружение.
Если нужного Python ещё нет, uv может предложить или выполнить его загрузку.

```sh
uv run --no-project --python 3.14.7 python examples/orbit_demo.py
uv run --no-project --python 3.14.7 python -B scripts/run_portable_tests.py
uv run --no-project --python 3.14.7 python scripts/check_publication.py
```

Проверки не скачивают астрономические данные. Unit tests проверяют численные
примитивы, контракты, признаки, разделение объектов и поведение селекторов.
Они не заменяют полный benchmark. `check_publication.py` проверяет локальные
Markdown-ссылки в новых входных документах, соответствие GIF опубликованному manifest.

Публичная обёртка обнаруживает все 325 исходных тестов. Пять заранее
перечисленных тестов требуют двух raw-файлов, исключённых из Git: они получают
явный `SKIP` с именем недостающего файла. Остальные 320 выполняются; любые
другие ошибки завершают проверку неуспешно. При наличии полного локального
архива выполняются все 325. Замороженные исходники тестов не менялись.

Пример интегрирует синтетическую круговую орбиту и сравнивает положение
с точным аналитическим решением. Он не использует обученные модели и
не повторяет score confirmation100.

## 2. Новый прогноз

[API v4](SELECTOR_V4_USAGE.md) описывает `forecast_online`, начальное состояние,
эфемериды, NG availability и статусы. Обученные модели, как и полные данные,
остаются вне Git; их наличие необходимо для запуска научного API.

Полный исследовательский loader ссылается на локальные `data/` и `outputs/`.
Поэтому его команды не являются готовым one-command forecast из чистого клона.
Для нового запуска сначала нужны входы, перечисленные в [DATA_GUIDE](DATA_GUIDE.md):
центр, ICRF, TDB, AU/AU per day, geometric vectors и provenance каждого файла.

Новый набор входов и новые расчёты должны сохраняться в отдельном namespace.
Повторный запрос к живому Horizons может дать другой snapshot; совпадение
номера тела само по себе не означает побайтовое совпадение исходной эфемериды.

## 3. Полное повторение исторического эксперимента

Для exact reproduction нужны оригинальные raw snapshots, checksum manifests,
сохранённые development-матрицы, модели и freezes. В этом публичном выпуске
такой полный архив **не распространяется**. Из одного клона нельзя независимо
восстановить все заявленные score без этих входов.

Сохранённые локальные результаты проверяются предусмотренными verifier-командами;
завершённые training/matrix/cost этапы не перегенерируются.

- [Отбор и audit выборки](SELECTOR_CONFIRMATION100_SAMPLE_AUDIT.md).
- [Отчёт и границы timing](SELECTOR_CONFIRMATION100_REPORT.md).
- [Прежний fresh holdout: воспроизведение](FRESH_HOLDOUT12_REPRODUCIBILITY.md).

## 4. Иллюстрации

Готовые GIF/SVG отображаются непосредственно на GitHub. Рядом с GIF сохранены
scene JSON, PNG, audit и manifest. Быстрая проверка сравнивает их SHA-256 и размеры.
Она подтверждает целостность опубликованного комплекта, но не пересчитывает
траектории и не заменяет исходный координатный аудит.

Пересборка GIF использует Swift, AppKit и ImageIO на macOS и требует полного
локального архива. Для чтения репозитория и запуска Python-примера Swift не нужен.
[Подробная методика визуализации](TRAJECTORY_RENDERING.md).
