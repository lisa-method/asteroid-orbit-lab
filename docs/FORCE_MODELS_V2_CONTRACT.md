# Общая сборка сил v2 — 2026-09-07

Пользователь разрешил интегрировать результаты outlier audit в общую программу.
Контракт записан до запуска новой матрицы. Все 30 development объектов уже
просмотрены: новая оценка является post-hoc regression / teacher matching.
Она не заменяет frozen validation development30 и не является final test.

## Состав кандидатов

Состав сил задаётся явными флагами, имя модели служит только меткой.
Одна конфигурация выбирается на весь recursive rollout. Все включённые силы
вычисляются на каждом этапе RK4 по прогнозируемым положению и скорости.
Earth J2 содержит direct-minus-indirect члены в гелиоцентрической системе.
Идентификаторы астероидов не участвуют в построении силы или выборе модели.

| Метка | Состав |
|---|---|
| V2-B2 | Солнце, чистый two-body baseline |
| V2-P | Солнце, девять планетных perturbers, Earth J2, доступные NG |
| V2-P-GR | V2-P + solar Schwarzschild |
| V2-P-GR-SB16 | V2-P-GR + прежние 16 массивных астероидов |

Earth J2 в первой версии включён во все планетные кандидаты без порога
расстояния. Его полезность и стоимость оцениваются, не предполагаются.
NG при наличии включены во все планетные кандидаты; независимые переключатели
доступны для последующих ablations. Старые модели, константы, raw и результаты
сохраняются. Плутон, поля других планет и их отдельные спутники в эту матрицу
не добавляются. Массивные системы гигантов остаются прежними monopoles.

## NG inputs и граница доступности

Новый тип входных данных содержит точные A1/A2/A3 и distance-law параметры,
источник и SHA-256, временную границу доступности, основание этой границы,
дату orbit solution и необязательные sigma трёх коэффициентов.
Отсутствие параметров и отсутствие их неопределённости обозначаются явно;
ни то, ни другое не превращается в измеренный ноль.

Raw adapter читает физические параметры только из header до $$SOE, без
будущих строк состояния. Неполный, неоднозначный или нечисловой NG header
отклоняется. Параметры не подгоняются по residuals. Векторные начальные условия
по-прежнему задаются отдельно; reference доступен только evaluator.

Автоматическое подтверждение доступности опирается на сохранённую дату
получения raw, а не на старую osculating epoch или одну дату orbit solution.
Для даты UTC применяется консервативная граница: полночь через два календарных
дня, выраженная в JD TDB. Это запас на неизвестное время внутри даты и
разницу шкал, не точный алгоритм UTC–TDB. Неизвестная или более поздняя дата
исключает NG из политики if_available; required в таком случае выдаёт ошибку.
При явном внешнем вводе caller должен передать доказуемую границу в JD TDB.
Доступность фиксируется на начало rollout и не меняется с его будущей эпохой.

Метаданные с неизвестным NG помечают ограничение полноты физики. Наличие
sigma фиксируется, но эта версия возвращает nominal trajectory: ковариация
начального состояния и NG, корреляции и propagation uncertainty ещё не решены.
Ни наличие NG, ни успешный regression не дают гарантии будущей ошибки.

## Матрица, численная проверка и стоимость

Прежние 30 объектов, пять горизонтов 7/30/90/180/365 дней, четыре кандидата:
600 model/case records. Метки train/validation сохраняются для сопоставления;
любая новая оценка на старых 12 validation объектах называется replay.

Те же initial states, hourly planetary ephemerides, daily + five-minute
reference grid, стандартные единицы AU/day, Sun-centred ICRF/FRAME, geometric
vectors, TDB. Adaptive RK4 production scale 0.5, fine scale 0.25, default
step 0.0625 дня. Сохраняются accepted endpoints для обеих траекторий.
Три годовых production повтора дают измеренные causal timing prefixes для
всех пяти горизонтов; один fine run проверяет step sensitivity. Сверяется
повторяемость production. Сохраняются position/velocity/RTN errors и
max production/fine distance на одинаковой reference сетке.

Достаточность: sampled max position error ≤ 0.1/1/10 km и step difference
≤10% выбранного допуска. Неуспех сохраняется в denominator. Возрастание
числа сил не предполагает монотонного улучшения. Prefix timings относятся
к propagator, не являются измерением полного operational selector.

Сначала unit tests композиции, ограничения входов и воспроизведение v1 при
выключенных поправках. Затем smoke на новом пути и полная матрица. Источники,
конфигурация, контракт и raw inputs фиксируются хэшами; runtime записывается.
Resume допускается только для совпадающего источника, входов и Python runtime.
Результаты пишутся в outputs/force_models_v2, subset smoke имеет отдельный
namespace. Завершённые результаты не переписываются повторным запуском.

## Выбор модели и последующая независимая проверка

Старые правила не считаются откалиброванными для новых сил. Первое v2 правило
может быть заново обучено только на прежних 18 train объектах: по горизонту
использовать максимальную effective error max(error, step_difference/0.1)
для каждого кандидата и измеренную медианную стоимость. Выбирать самый дешёвый
кандидат, удовлетворяющий эмпирическому пределу. Когда таких нет, возвращать
явный fallback с самым полным кандидатом. Этот предел не является гарантией.
Идентичность объекта, дата события и reference ошибки не являются входами выбора.

Для скоростного вывода нужны прямые повторы всего v2 вызова и постоянных
кандидатов на одинаковых случаях, с отдельным shared cold load. Сравнение
по уже сохранённым v1 timing не является контролируемым замером overhead J2.
Основной прямой замер v2 заранее ограничен допуском 1 km: все 60 replay окон,
три повтора selector и постоянного кандидата с чередованием порядка. Для
постоянного кандидата выбирается самый дешёвый по матрице из покрывающих всё
разрешимое подмножество; если такого нет, используется наиболее полный.
Время включает inference, сборку силы и rollout при уже загруженных initial
state, NGInput и эфемеридах. Чтение raw и offline reference evaluation вне
таймера. При 0.1/10 km приводится accuracy replay; нового full-cost вывода
по этим двум допускам данный замер не даёт.
После фиксации метода необходим свежий whole-object/event holdout; старые
12 объектов для независимого результата использовать повторно нельзя.

Независимый solver, полная EIH, uncertainty propagation и надёжное обнаружение
всех no-candidate случаев остаются отдельными исследованиями. Эта интеграция
добавляет проверенные физические компоненты, а не обученную residual поправку.
