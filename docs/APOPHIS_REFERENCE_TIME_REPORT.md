# Апофис: согласованность эталона и вычисление времени

2026-09-08. Post-hoc audit одного ранее исследованного объекта. Контракт
зафиксирован до новых запросов и прогнозов; повтор старого запроса добавлен
отдельным amendment до интеграций. Физические силы и их параметры не менялись.
Это проверка propagation против model-derived Horizons, не наблюдательная
точность и не новая оценка selector.

**Проверка завершена: 18 годовых интеграций. Найдены воспроизводимое
расхождение reference рядов до 17.212 km и чувствительность численной
арифметики. При согласованном выборе initial state / teacher остаток
сохраняется около 10.4 km. Простая замена reference не решает задачу.**

## Что проверяли в reference

Для одного решения JPL#220 с одинаковыми nominal NG, центром Солнца,
ICRF/FRAME, геометрическими AU-D и TDB получили четыре ряда:

| Границы запроса | Шаг | Число состояний |
| --- | --- | ---: |
| 2029-01-01 — 2030-01-01 | 1 сутки | 366 |
| 2029-01-01 — 2030-01-01 | 1 час | 8761 |
| 2029-04-10 — 2029-04-18 | 1 сутки | 9 |
| 2029-04-10 — 2029-04-18 | 1 час | 193 |

Все четыре ряда **точно совпадают на общих датах**, как и их общие узлы
с прежними подробными рядами 5 min / 36 h и 5 min / 8 d. Частота вывода сама
по себе это расхождение не объясняет.

Однако прежний суточный запрос 2020-01-01 — 2030-12-31 даёт другие состояния:

| Дата TDB | Разница положения между старым длинным и новым годовым рядом |
| --- | ---: |
| 2029-01-01 | 3.609 m |
| 2029-04-01 | 4.045 m |
| 2029-04-13 00:00 | 4.150 m |
| 2029-04-14 00:00 | 6.403 m |
| 2029-04-18 | 86.707 m |
| 2029-07-01 | 2.017723 km |
| 2030-01-01 | **17.211816 km** |

Разница скоростей: 7.03235e-7 m/s на старте и 0.00212766 m/s в конце года.
Все расстояния вычислены из пар трёхмерных состояний, не из разности
скалярных ошибок наших моделей.

Чтобы отделить дату получения данных от параметров запроса, повторили
**точный URL из старого manifest**. Все 4018 состояний повторного ответа
совпали со старыми точно, включая скорости. Полное raw JSON отличается
служебными сведениями и потому имеет другой hash. У старого и нового
годового запросов отличаются только START_TIME и STOP_TIME.

Для этих проверенных запросов подтверждена воспроизводимая зависимость
состояний от границ запроса при одном обозначении orbit solution. Причина
внутри JPL этим опытом не установлена. Официальное руководство описывает
интеграцию small-body solution от эпохи osculating elements к началу
запрошенной таблицы, в том числе с обращением направления времени.
Это возможный механизм зависимости от пути интеграции, а не доказанный
диагноз данной реализации. [Horizons manual](https://ssd.jpl.nasa.gov/horizons/manual.html#numerical-integration).

## Как отделяли арифметику от изменения физики

Состав сил во всех ветвях один: Sun + девять planetary perturbers + solar
Schwarzschild + SB16 + nominal NG + Earth J2 с IAU mean pole. Повторно
использованы подробные Earth/Moon 5-min узлы на Apr 10–18, Venus 15 min,
остальные планеты и SB16 daily. Будущие состояния Апофиса используются
только при оценке; прогноз не перезапускается из них.

Три представления времени:

- **legacy:** прежние абсолютные JD в solver/force callbacks;
- **relative float:** дни от Jan 1 2029 во всём solver/RHS/interpolation,
  но узлы получены вычитанием исходных double JD;
- **relative calendar:** те же относительные дни, но расстояния между узлами
  сначала вычислены как целочисленные Gregorian TDB calendar differences.

Последний вариант сохраняет координаты/скорости каждого входного узла
и устраняет округление абсолютного JD при получении локального времени.
Одна ULP double JD в этом интервале — около **40.23 микросекунды**.
Это не неопределённость физического времени, а разрешение его представления.
Арифметическая группировка Hermite сохранена; у J2 изменён только способ
вычисления времени для той же формулы оси. TDB labels не интерпретируются
как UTC, timezone-aware строки отвергаются.

Основная historical оценка остаётся на прежних 797 узлах. Это смешанная
daily/refined reference-сетка, сохранённая для точного сравнения со старыми
результатами. Дополнительно каждый forecast оценивается против каждого
из восьми явно названных reference рядов **на общих датах без интерполяции
target teacher**. Поэтому annual-hourly оценка не означает проверку всех
8761 часов: берутся только совпадающие integration stops.

Для проверки начального состояния выполнено перекрёстное сравнение:
старый и новый initial state, каждый против старого и нового годового
reference. Выбор более удобного teacher не является улучшением модели.

## Результат изменения временной арифметики

Максимальная position error на старой основной сетке, km; исходное старое
initial state. DP означает Dormand–Prince 5(4); tight/tighter/extreme имеют
rtol 1e-10/1e-12/1e-13 и зафиксированные в baseline абсолютные допуски.
RK4 scale — множитель прежнего encounter-aware шага, не шаг в сутках.

| Представление времени | DP tight | DP tighter | DP extreme | RK4 0.5 | RK4 0.25 | RK4 0.125 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| legacy | 10.573482 | 10.521489 | — | 11.596986 | 9.599923 | — |
| relative float | 10.428236 | 10.418807 | 10.411700 | 10.605318 | 10.173157 | 11.445775 |
| relative calendar | 10.421295 | 10.418411 | 10.418126 | 10.613735 | 10.175775 | 11.454025 |

Все четыре legacy записи воспроизведены **точно** по четырём сохранённым
position/velocity summaries. Временная arithmetic ablation не меняет
физические силы. Legacy → relative calendar при DP tighter сдвигает
предсказанную траекторию максимум на **103.205 m**.

Сходимость оценивалась отдельно, по расстоянию между парными прогнозами
на каждой общей дате. Это не разница двух скалярных максимумов:

| Представление / initial state | DP tight → tighter | DP tighter → extreme | RK4 0.5 → 0.25 | RK4 0.25 → 0.125 |
| --- | ---: | ---: | ---: | ---: |
| legacy / old | 52.280 m | — | 1997.464 m | — |
| relative float / old | 16.662 m | 7.108 m | 432.254 m | 1272.857 m |
| relative calendar / old | 13.740 m | **0.403 m** | 438.052 m | 1278.490 m |
| relative calendar / new | — | **1.429 m** | — | — |

У старого initial state конечная DP tighter/extreme разница 0.326 m,
а максимум вдоль траектории 0.403 m. Разность скалярных годовых maxima
0.285 m не является этой парной метрикой. Calendar вместо float knots при
одинаковом DP extreme сдвигает forecast на 6.428 m.

Временная арифметика существенно улучшила устойчивость DP. Однако три
настройки одного адаптивного метода не дают строгой границы numerical error.
RK4 в этой матрице **не сходится устойчиво**: последний шаг изменения
увеличивает расхождение. Независимое межметодное подтверждение метровой
точности по-прежнему отсутствует. Общая численная задача не объявляется
закрытой, а relative module пока является отдельной исследовательской ветвью.

## Проверка initial state: почему 6.8 km были бы ложным улучшением

Сравнение DP extreme / relative calendar на одинаковых **366 суточных
датах**, отдельно от mixed historical 797 grid:

| Источник начального состояния | Старый длинный teacher | Новый годовой teacher |
| --- | ---: | ---: |
| Старый длинный ряд | **10.418126 km** | 6.798964 km |
| Новый годовой ряд | 27.672234 km | **10.461737 km** |

Если заменить только reference таблицу, прежний прогноз выглядит лучше:
10.418 → 6.799 km. Но при одновременном использовании согласованного нового
initial state ошибка снова **10.462 km**. Остаток порядка 10 km сохраняется
в обоих согласованных вариантах, поэтому несогласованность источников его
целиком не объяснила.

Изменение начального шестимерного состояния (3.609 m по позиции и
7.03235e-7 m/s по скорости) сдвигает наш годовой forecast максимум на
**17.255390 km**. Это парное распространение двух конкретных initial states
через близкий земной пролёт. Отношение этих расстояний нельзя переносить
на произвольное направление ошибки или использовать как uncertainty bound.

В согласованной новой ветви ошибка составляет 1.948 m на Apr 1,
2.604 m на Apr 13 00:00, 4.726 m на Apr 14 00:00, 49.209 m на Apr 18,
1.250 km на Jul 1 и 10.462 km на Jan 1 2030. Это поддерживает дальнейшее
изучение того, как небольшой промах возле пролёта превращается в годовой
остаток; оно не идентифицирует конкретную недостающую силу.

## Что переносить в программу и что осталось

1. Хранить request bounds, orbit solution, coordinate/time contract и
   provenance начального состояния вместе с reference. Один номер JPL#220
   не гарантирует совпадения таблиц. Проверять перекрытия **до** объединения
   рядов, сохранять несовместимые teachers отдельно.
2. Использовать относительное время во всей цепочке solver → force →
   ephemeris; восстанавливать точные временные узлы из TDB calendar либо
   эквивалентного представления с разделённой целой/дробной частью JD.
   Этот опыт даёт основание для будущей версии общего propagator, но не
   изменяет frozen operational v2 автоматически.
3. До приписывания остатка слабым силам проверить RK4 отдельно: согласование
   фактически продвинутого времени с шагом состояния, накопление округлений
   и поведение вблизи пролёта. Затем повторить независимое межметодное
   сравнение при едином initial/reference contract. Причина поведения RK4
   здесь ещё не установлена.
4. После этого исследовать остаток при неизменном teacher и проверять
   дополнительные физические члены отдельной ablation. В текущем опыте
   допуск 1 km для годового Апофиса не достигнут.

Прежние 60/60 fresh-holdout и другие selector scores не пересчитывались.
Апофис остаётся inspected stress case. Новых ML результатов, коэффициентов
коррекции или оценок наблюдательной неопределённости этот audit не создаёт.

## Воспроизведение и сохранение

Проверки прошли: **146 unit tests**, 18 immutable checkpoints, 432022
accepted endpoints с начальными состояниями, 115992 scalar position/velocity
error values и 89264 paired scalar values (56 пар). Все requested states
точно совпадают с соответствующими native accepted endpoints; velocity
проверяется вместе с position. Четыре legacy baseline полностью воспроизведены.
Дополнительные шесть проверок с намеренным повреждением копии записи
отвергли неправильные времена, скорость, дубли времени, NaN внутри trace,
несогласованный initial source и неверную velocity summary.

Двенадцать manifests содержат 153 записи и **134 уникальных raw-пути**:
SHA-256, размеры, отсутствие tracking и Git exclusion проверены. Пять
новых raw-файлов занимают 2 656 223 bytes. Полные данные и traces ignored;
отчёт включён в локальную историю физической диагностики. Публикации нет.

Артефакты в `outputs/apophis_reference_time/`: `freeze.json`, `matrix.json`,
18 файлов `checkpoints/`, `verification.json` и компактный `diagnostics.json`.

и воспроизведение четырёх baseline records выполняются отдельно.
