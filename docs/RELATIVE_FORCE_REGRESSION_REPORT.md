# Общая модель J2/J3/J4: проверка на 30 объектах

Работа 8–9 сентября 2026; расчёты и offline audit завершены. Общая модель
доступна через [forecast API](RELATIVE_FORCE_USAGE.md). На всех 30 изученных
development объектах годовая ошибка по 366 суточным узлам меньше 100 m
в обеих ветвях: максимум 62.422 m без J3/J4 и 62.417 m с ними.
На шести контрольных телах межметодное различие DP/RK4 не превышает 7.203 cm.

Это перенос физического компонента на inspected regression set. Новый
selector не обучался, fresh holdout не открывался; прежние scores не меняются.
[Контракт](RELATIVE_FORCE_REGRESSION_CONTRACT.md) зафиксирован до расчётов.

## Что реализовано

В `src/relative_force_model.py` подробная модель собирается из общих сил:
Sun, переданные planet/system и SB monopoles, solar Schwarzschild, Earth J2,
NG при доступных на старте коэффициентах. Earth J3 и J4 — явные опции с
прежними IERS coefficients/rates и IAU mean-pole approximation. Идентификатор
астероида не выбирает формулу. Earth/Moon задаются раздельно; Mars и гиганты
используют те же system/planet conventions, что в frozen исходных данных.

`src/forecast_precise.py` принимает initial state, origin, horizon,
относительные exogenous ephemerides и физические/численные настройки.
Возвращает daily states и native endpoints; future asteroid reference и
даты эталонных событий в его входах отсутствуют. Проверяются единицы через
явный контракт, тип/длина состояния, покрытие ephemerides и NG availability.
Время считается относительно старта по TDB calendar labels.

Доступны DP5(4) и compensated RK4. DP API перезапускает контроллер на каждом
суточном интервале, передавая только собственное рассчитанное состояние;
RK4 использует прежний encounter-aware step selector и новое согласование
времени/компенсацию округлений. Оба сохраняют точные requested endpoints.
Перезапуск DP — зафиксированная особенность версии API, не новая наблюдаемая
поправка состояния. Подробности: [вызов и ограничения](RELATIVE_FORCE_USAGE.md).

## Проверенные результаты

120 DP forecasts: 30 объектов × две силы × tighter/extreme.
Ещё 12 compensated RK4: по первому объекту каждой из шести frozen страт,
обе силы, scale=0.25. Стартовые даты и порядок объектов исходного sample
сохранены. Во всех ветвях девять planet/system perturbers и SB16.

| Группа, по 5 тел | Диапазон max annual error baseline, m |
|---|---:|
| Сближения с Землёй | 20.385–62.422 |
| Сближения с Венерой | 6.418–42.298 |
| Сближения с Марсом | 8.458–31.057 |
| Сближения с Юпитером | 9.159–27.693 |
| Внутренние main-belt controls | 6.757–14.328 |
| Внешние main-belt controls | 1.049–6.326 |

При 0.1/1/10 km обе силы проходят 30/30 годовых daily windows, включая
empirical numerical gate ≤10% допуска. Максимальное DP tighter/extreme
различие — 1.1588 m; для шести controls дополнительно учитывается сравнение
с RK4. У остальных 24 независимый алгоритм в этой матрице не проверялся.
Метрики daily не заменяют максимум на прежней daily+refined сетке и не
ограничивают ошибку между узлами.

NG коэффициенты предоставлены и доступны на старте только для TU7 (613569).
У остальных 29 статус `not_provided`; отсутствие коэффициента не объявляется
доказанным отсутствием негравитационного ускорения. Здесь нет нового
эмпирического теста ветви `not_yet_available`; она покрыта программными тестами.

## Что дают J3/J4

Для WN5 (153814) max error меняется 29.7735 → 29.0028 m, векторный сдвиг
траектории 0.77083 m. Изменение **вектора поправки** между DP настройками
4.94 mm, так что эффект устойчив на масштабе около метра.

| Earth object | Baseline error, m | J3/J4 error, m | Max сдвиг от J3/J4, m | Изменение вектора эффекта между DP settings, m |
|---|---:|---:|---:|---:|
| 35396 | 62.422458 | 62.416579 | 0.006138 | 0.005741 |
| 292220 | 44.515375 | 44.514380 | 0.001073 | 0.005408 |
| 137108 | 29.627784 | 29.588963 | 0.039475 | 0.005524 |
| 893859 | 20.385236 | 20.386773 | 0.001547 | 0.001024 |
| 153814 | 29.773491 | 29.002846 | 0.770833 | 0.004942 |

Миллиметровые изменения у 35396/292220/893859 нельзя уверенно трактовать
как улучшение или ухудшение физики: они сравнимы с numerical sensitivity
парного эффекта. Формально четыре ошибки уменьшаются, одна увеличивается,
25 неизменны; эти счётчики не являются тестом физического превосходства.
У остальных 25 тел сохранённые DP состояния обеих ветвей совпадают точно
в обеих настройках, что означает неразличимость на этой численной точности,
а не математически нулевую силу.

Вывод для выбора модели: на этой выборке J3/J4 не меняют достаточность при
100 m/1 km. На отдельном близком пролёте Апофиса их эффект около 1.9235 km,
поэтому это полезная опция для соответствующего режима. Уместен общий
физический компонент с проверкой значимости, а не правило по имени тела.
Автоматическое условие включения и его стоимость ещё требуют отдельного
candidate/selector contract и свежей проверки.

## Связь с численной задачей Апофиса

Параллельный [аудит округлений](PRECISE_PROPAGATION_REPORT.md) содержит
ещё 36 прогнозов (24+12). Compensated RK4 сходится до сантиметров при
уменьшении шага; с compensated DP остаётся 1.24–1.27 m, критерий ≤1 m
не выполнен. J3/J4 force-effect vectors между алгоритмами различаются
на 2.12 cm / 1.57 mm для старого/нового initial.

Согласованная годовая Apophis teacher error после J3/J4 остаётся около
8.5 km. Численная нестабильность устранена на прежнем километровом масштабе,
но причина этого остатка не установлена. Прямая shape/spin/thermal модель
здесь не добавлялась; [следующий отдельный этап](RELATIVE_FORCE_USAGE.md)
должен учитывать совместимость shape/spin inputs и исключать двойной учёт A2.

## Верификация и воспроизведение

181 unit test проходит. Offline verifier заново вычисляет 96624 скалярные
ошибки позиции/скорости, проверяет 591140 native endpoints, все 132 записи
и 66 force pairs; дополнительно строит DP setting differences, 12
cross-solver comparisons и 30 effect-vector sensitivities. Проверены
initial state, daily/native equality, NG gates, object metadata,
configuration/source/runtime hashes. Все 137 raw-файлов в 13 manifests
проходят SHA-256/size/Git exclusion checks. Новых raw данных нет.

Общий force builder даёт точное равенство ускорений прежнему Apophis audit
в обеих ветвях на 797 сохранённых прогнозных состояниях. Это проверка
переноса арифметики сил, не независимая верификация самих физических формул.

```bash
env UV_CACHE_DIR=/private/tmp/astrophysics-ml-uv-cache UV_OFFLINE=1 UV_PYTHON_DOWNLOADS=never uv run --no-project --python-preference only-system --python 3.14.7 python -B src/verify_relative_force_regression.py
env UV_CACHE_DIR=/private/tmp/astrophysics-ml-uv-cache UV_OFFLINE=1 UV_PYTHON_DOWNLOADS=never uv run --no-project --python-preference only-system --python 3.14.7 python -B src/run_relative_force_regression.py --resume
```

На завершённом наборе `--resume` читает checkpoints. Для новых настроек
нужна новая версия. Локальные `outputs/relative_force_regression/` исключены
из Git; matrix index ссылается на отдельные immutable trace checkpoints.

Время каждого вызова сохранено как диагностический показатель. Полная
online стоимость с общими входами, screening и selector inference в этом
эксперименте не измерялась; нового speedup заявления нет. Старые numerical
modules/results, selector rules и fresh holdout сохранены. Новых
зависимостей, установки среды, commit или публикации не было.
