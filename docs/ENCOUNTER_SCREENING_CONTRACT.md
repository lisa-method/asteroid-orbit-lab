# Первый этап предварительного прогноза сближений

Дата: 2026-09-07. Пользователь выбрал следующий порядок: сначала дешёвая
приблизительная траектория и оценка ожидаемых сближений, после этого — учёт
дополнительных малых возмущений. Конфигурация первого эксперимента:
`configs/encounter_screening_pilot6.json`, записана до основного запуска.

## Входы и результат

`forecast_encounters` получает только начальное состояние астероида, epoch,
горизонт, константы и daily planetary ephemerides. Физика preliminary rollout:
солнечная two-body B2 с существующим ограничением RK4 step по расстоянию до
Солнца. Планеты используются для геометрии, но не входят в это ускорение.
Никакие новые силы, fitted NG или ML не добавляются.

Для каждого из девяти perturbers возвращаются минимум одновременного
расстояния в заданном окне, время от начала, относительная скорость,
гелиоцентрическое отношение ускорений и диагностический Hill proxy у минимума.
Пересечение геометрических путей в разные моменты не считается сближением.
Начальные и конечные минимумы сохраняются с boundary flag: это может быть
уже идущее или ещё не завершившееся сближение.

Основные критерии тревоги: расстояние ≤ 0.001, 0.01 и 0.05 AU. Пороги
exploratory, зафиксированы до этого запуска и не означают границу опасности
или гарантию точности будущего propagator. Пока задача — обнаружение хотя бы
одного сближения до порога в окне для данной пары тел. Полный каталог всех
отдельных пролётов и event matching — дальнейшая работа.

## Сравниваемые варианты

| Вариант | Сетка B2 | Поиск минимума |
| --- | --- | --- |
| daily_nodes | 1 day | Только расстояния в узлах |
| daily_hermite | 1 day | Узлы и stationary points между ними |
| six_hour_hermite | 0.25 day | Узлы и stationary points между ними |

Между узлами relative state задаёт cubic Hermite curve. Ищутся все корни
`r(u) · dr/du = 0` в [0,1] и сравниваются с endpoints. Корни quintic polynomial
изолируются рекурсивно через корни производной, затем уточняются bisection.
Учитываются несколько минимумов, касательные корни и вырожденные случаи.
Это численный минимум интерполянта; точность underlying траектории требует
отдельной проверки. Уменьшение output cadence также меняет остановки RK4,
поэтому сравнение 1 day и 6 h может включать малые различия интегрирования.

`eta_helio_at_closest` использует direct и indirect planetary acceleration,
делённое на модуль солнечного ускорения. `rho_sun_proxy_at_closest` использует
приближение `R = |r_planet| (mu_planet / (3 mu_sun))^(1/3)`; для связанной с
Землёй Moon это поле null. Это величины у минимума расстояния, не максимальный
eta или минимальный rho всего интервала. При нулевом расстоянии сохраняются
zero-separation flag и null вместо сингулярного eta.

## Оценка без подглядывания в будущее

Основная матрица: шесть уже изученных объектов, начало 2029-01-01,
горизонты 7/30/90/180/365 days. Отдельно — Apophis со стартами за
7/30/90/180 дней до 2029-04-13 и окончанием через два дня после этой даты.
Дата события используется для заранее заданных **оценочных окон**, но не
передаётся в screening algorithm и не управляет его сеткой.

Reference evaluator отдельно читает будущие Horizons asteroid states.
Его сетка содержит объединение исходных узлов астероида и планеты внутри
окна и endpoints. Для Apophis/Earth/Moon используется сохранённое уточнение
с шагом пять минут. Ground minima ищутся на соответствующих cubic curves;
пять минут тоже не дают строгой непрерывной истины. Сохраняется шаг исходных
узлов вокруг найденного reference minimum для оценки качества эталона.

Сначала создаются `forecast_features.json` и `reference_minima.json`, затем
они сравниваются в `results.json`. TP/FN/FP/TN считаются для каждой пары
case/body на каждом пороге. В отчёте main и lead-time группы разделены:
вложенные горизонты и один Apophis event не являются независимыми наблюдениями.
Все пропуски и ложные тревоги сохраняются, а не отбрасываются при анализе.

## Стоимость и воспроизведение

Каждый горизонт исполняется отдельным прогнозом. Три serial timing повтора
меняют порядок вариантов; runtime включает force setup, B2 integration,
планетную интерполяцию и полный поиск минимумов. Загрузка resident ephemerides
и offline reference computation показываются отдельно. Пока не измеряется
ускорение выбранной основной force model или стоимость ML.

В ignored `outputs/encounter_screening/pilot6/` хранятся features, reference,
evaluation, timing trials, config snapshot, conventions и SHA-256 кода,
конфигураций и manifests на начало запуска. Raw остаются неизменными.

```bash
env UV_CACHE_DIR=/private/tmp/astrophysics-ml-uv-cache UV_OFFLINE=1 UV_PYTHON_DOWNLOADS=never uv run --no-project --python-preference only-system python -B src/run_encounter_screening.py --root . --config configs/encounter_screening_pilot6.json
```

Итог: [ENCOUNTER_SCREENING_PILOT6_REPORT.md](ENCOUNTER_SCREENING_PILOT6_REPORT.md).
Новые объекты и object/event splits ещё не сформированы. После этого пилота
нужно решить, где B2-геометрия годится как предупреждение, где требуется запас
или другой предварительный propagator, и проверить это на независимых событиях.
Выбор достаточной основной модели и дополнительные малые силы — следующие этапы.
