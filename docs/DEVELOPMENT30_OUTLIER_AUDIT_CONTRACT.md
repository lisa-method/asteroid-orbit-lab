# Диагностика двух объектов development30 — 2026-09-07

Post-hoc исследование по запросу пользователя о пяти оставшихся окнах и
возможном влиянии пояса астероидов, спутников и Плутона. Это два объекта:
153814 (2001 WN5), горизонты 90/180/365 суток, и 613569 (2006 TU7), 180/365.
Исходный development30 split, правила и результаты остаются неизменными.

До запуска новых force variants обнаружены две конкретные гипотезы:

- 153814 сближается с Землёй примерно до 248711 km; проверить Earth J2
  с ранее принятыми константами и IAU mean pole из существующего модуля.
- У 613569 raw Horizons header содержит A2=1.18779071272e-13 AU/day²,
  A1=A3=0, ALN=1, NM=2, NK=0, NN=5.093, R0=1. Эти параметры исключены
  из исходных четырёх кандидатов. Проверить точное nominal NG из header;
  коэффициенты по новым residual не подгонять.

Дополнительная контрольная гипотеза пользователя: Pluto system point mass.
Загружен один анонимный Horizons ряд body 9, daily 2027-12-30–2029-06-01,
Sun-centred ICRF/FRAME, geometric, TDB, AU/day. GM системы 975.5 km³/s²
из https://ssd.jpl.nasa.gov/astro_par.html. Это суммарная масса в системном
барицентре; массу Харона отдельно не добавлять.

География: диапазон гелиоцентрического расстояния в годовом reference,
минимумы расстояний до всех имеющихся планет/Луны, 16 астероидных perturbers
и Плутона; первая ошибка >1 km и ошибка до/после выбранного события.
Это offline диагностика, даты и reference не становятся forecast features.
Параметры из orbital header относятся к указанной в нём эпохе, а не
автоматически к началу нового прогнозного окна.

Для каждого объекта сравнить исходный B3+GR+SB16, одно адресное дополнение
(Earth J2 либо nominal NG), только Pluto и адресное дополнение + Pluto.
Одинаковое начальное состояние, общий прежний adaptive RK4, daily targets,
accepted endpoints; production scale 0.5 и fine scale 0.25. Сначала сверить
новый baseline path с frozen validation: max-error и step difference на
7/30/90/180/365 сутках должны совпасть в пределах 1e-5 km.

Оценка на прежней daily + five-minute reference сетке; max position error,
velocity/RTN, production/fine difference и shift относительно baseline.
Достаточность сохраняет исходные условия: ошибка ≤ допуск, разница шагов
≤10% допуска. Межузловой максимум и независимая численная сходимость не
гарантируются. Одного production/fine запуска на variant достаточно для
этого accuracy audit; сравнений скорости по нему не делать.

Результаты только в outputs/development30_outlier_audit; raw Плутона отдельно
в data/raw/development30_outlier_audit и отдельном checksum manifest.
Хэши исходных numerical modules и inputs проверяются до запуска и сохраняются.
Этот эксперимент не переоценивает успех frozen selector и не является новым
закрытым test. Если найдено улучшение, перенос силы в рабочую систему требует
новой версии candidate contract и проверки доступности параметров на старте.

Независимый solver, полная EIH-релятивистика, подробные поля/спутники других
планет и дополнительные астероиды остаются следующими проверками при наличии
необъяснённого остатка. Их необходимость не предполагается заранее.
