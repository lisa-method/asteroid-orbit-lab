# Апофис: модель эталона, ось Земли и солнечный J2

Дата: 2026-09-09. Завершён отдельный диагностический эксперимент:
четыре физических варианта, два допуска compensated DP и compensated RK4.
Девять новых propagations и три неизменных baseline traces из прошлого
эксперимента. [Контракт до расчётов](APOPHIS_GRAVITY_CONVENTIONS_CONTRACT.md).
Это post-hoc аудит изученного пролёта, без новой оценки selector/holdout.

## Главный результат

Найдены конкретные различия моделей, но километровый остаток не устранён.
Лучшая из проверенных сейчас ветвей даёт **7.292 km** вместо 10.464 km.
Добавление солнечного J2 ухудшает совпадение с teacher. Причина оставшегося
расхождения не установлена; точность 1 km и 100 m не достигнута.

Существенное уточнение прежнего вывода: **все восемь сохранённых ответов
Horizons для Апофиса объявляют Earth J2 only** (`EOBL_MOD = 2x0`) и
`EOBL_LIM = 1.000 au`. Следовательно, уменьшение ошибки после Earth J3/J4
не является свидетельством восстановления пропущенных гармоник именно этого
teacher. Численно подтверждённый эффект около 1.924 km остаётся верным;
его интерпретация как причины ошибки была бы слишком сильной. Добавленная
сила могла частично компенсировать другое расхождение.

## Проверяемые гипотезы

У нас Earth J2 использовал меняющийся IAU mean pole. В авторском
[коде ASSIST](https://github.com/matthewholman/assist/blob/main/src/forces.c)
земная ось фиксирована вдоль J2000 z, а комментарий связывает это с Horizons.
Это основание проверить соглашение, а не доказательство устройства JPL#220.
Для Солнца там используются RA=286.13°, Dec=63.87°.

Из открытого [заголовка DE441](https://ssd.jpl.nasa.gov/ftp/eph/planets/ascii/de441/header.441)
получены `J2SUN = 2.19613915165298248e-7` и `ASUN = 696000 km`.
Это reference radius модели. Солнечная квадрупольная поправка в прежней
модели отсутствовала. Использована собственная ранее проверенная vector J2
формула, без заимствования реализации ASSIST.

Сохранены все остальные силы: Sun/planet/SB16 monopoles, solar Schwarzschild,
номинальные A1/A2/A3 и Earth J2. Коэффициенты по residual не подгонялись.
Earth J3/J4 во всех четырёх вариантах выключены. Прежние Earth J2/radius
сохранены для изоляции факторов; DE441 J2E отличается от нашего на
−5.54e-8 относительно, этот фактор отдельно не распространялся.

## Результаты на одинаковом initial и teacher

Старт 2029-01-01, горизонт 365 дней, initial из annual-hourly запроса;
основная оценка по совпадающему annual-daily teacher. Общая диагностическая
сетка содержит 797 точек; ошибки по восьми reference таблицам хранятся
раздельно. Ни один будущий state астероида не входит в force callback.

| Вариант | DP ultra: max daily error, km | RK4 fine: max daily error, km |
|---|---:|---:|
| Прежняя модель, IAU Earth J2 | 10.463895 | 10.462653 |
| Только фиксированная ось Earth J2 | 7.292059 | 7.290829 |
| Только солнечный J2 | 15.606666 | 15.605430 |
| Фиксированная земная ось + солнечный J2 | 12.422688 | 12.421455 |

Все четыре варианта сохраняются. Величина reference error не обязана
уменьшаться при добавлении сил. Меньшая ошибка у fixed-pole ветви сама по
себе не делает фиксированную земную ось более точной моделью реальной Земли
или универсальным выбором для остальных объектов.

DP extreme/ultra различаются на 0.147–0.165 m; DP ultra/RK4 — на
1.235–1.242 m. Прежний критерий ≤1 m **не выполнен** во всех четырёх
ветвях. Это эмпирическая численная чувствительность, не строгая граница
ошибки относительно реальной орбиты.

Парные векторные эффекты устойчивее абсолютных траекторий: fixed pole
сдвигает результат на 3.330501 km, Sun J2 — на 5.143700 km, обе поправки —
на 2.150316 km относительно baseline. Разность этих **векторов эффектов**
между DP и RK4 составляет соответственно 5.33, 5.92 и 6.66 mm. Поэтому
километровые сдвиги подтверждены двумя алгоритмами, хотя абсолютный
метровый критерий остаётся открытым. Эффекты нельзя складывать как нормы
или отождествлять с уменьшением scalar reference error.

Пример роста ошибки DP ultra, **метры**:

| День от старта | Прежняя модель | Только fixed pole | Только Sun J2 | Обе поправки |
|---|---:|---:|---:|---:|
| 30 | 0.189 | 0.189 | 0.289 | 0.289 |
| 90 | 1.948 | 1.948 | 2.990 | 2.990 |
| 102, до ближайшего пролёта | 2.604 | 2.606 | 4.006 | 4.007 |
| 104 | 15.522 | 20.910 | 23.723 | 28.045 |
| 180 | 1217.434 | 963.534 | 1798.228 | 1486.979 |
| 365 | 10463.895 | 7292.059 | 15606.666 | 12422.688 |

Расхождение возникает ещё до пролёта. Fixed pole почти не меняет эти ранние
метры, а сразу после пролёта даже увеличивает ошибку. Значит, его годовое
улучшение нельзя трактовать как устранение всей причины. Малые различия
на входе в сближение преобразуются в большие различия последующей орбиты.
Из одной пары нельзя получить универсальный коэффициент усиления или
вероятностный интервал реального положения.

## Что ещё проверять

1. **Полную релятивистскую модель и систему отсчёта.** Сейчас есть только
   солнечный двухтельный Schwarzschild. Полная EIH/PPN модель содержит
   дополнительные члены и требует согласованных barycentric states.
   Нельзя получить её простым суммированием отдельных Schwarzschild поправок
   планет в heliocentric frame. Нужен независимый backend с проверенными
   силами, константами и эфемеридами.
2. **Пакет исходных эфемерид и номинальную модель учителя.** Сравнить весь
   состав perturbers, GM, интерполяцию и движение Солнца. Pluto проверялся
   на WN5/TU7; это не отдельная оценка его усиленного эффекта для Апофиса.
   Cutoff Earth J2 также сохранён как различие соглашений: на нашей
   baseline requested grid расстояние до Земли 0.000254–0.461 au, то есть
   target не пересекает указанный порог 1 au на этих узлах.
3. **Чувствительность к начальному шестимерному состоянию и NG.** Проверять
   вариационные уравнения или симметричные малые возмущения из forecast-time
   inputs. Если covariance неизвестна, показывать sensitivity, а не
   придумывать вероятности. Старое различие двух initial/teacher запросов
   остаётся отдельным provenance эффектом.

[Holman et al. (2023)](https://arxiv.org/abs/2303.16246) проверяют ASSIST
против JPL small-body integrator, включая Апофис 2029. Они описывают
согласие менее сантиметра до встречи и около 500 m через 1000 дней.
Это другой эксперимент и другой эталон, а не наша достигнутая точность.
Он показывает полезность согласования полного набора сил и независимой
интеграции; текущие 7 km нельзя объявить непреодолимым физическим пределом.
ASSIST здесь не установлен и не запускался.

## Как обращаться с похожими телами

Предлагается общий класс **прогнозов через сильное гравитационное рассеяние**.
Класс определяется геометрией и чувствительностью прогнозируемого сближения,
горизонтом и допуском. ID объекта не выбирает уравнения.

- Сначала предварительный causal rollout: одновременные расстояния,
  relative velocity, отношение ускорений, расстояние в Hill radii.
- Если encounter требует уточнения, подробный кандидат выбирается на
  весь rollout согласно текущему контракту; мелкие шаги и сохранение
  геометрии события контролируются отдельно от набора сил.
- Для допустимого прогноза нужны согласованные inputs, numerical budget
  и проверенная достаточность сил. Согласие двух алгоритмов не гарантирует
  физическую точность. Если бюджет не подтверждён, возвращать траекторию
  с явным статусом `tolerance_unconfirmed` и причиной, а не обещать допуск.
- Правило такого предупреждения для **новых** объектов ещё нужно заморозить
  и проверить на event/object holdout. Нельзя использовать будущую
  reference error как его вход или обучать маршрутизацию по имени Апофиса.
- Форма, spin и thermal parameters могут быть персональными **данными**
  общей модели. Полную форму вводить, когда её вклад сопоставим с бюджетом
  и доступны нужные параметры. Текущие fixed-attitude COM опыты порядка
  метров не объяснили километровый mismatch. Для thermal расчёта нельзя
  повторно добавлять тот же эффект поверх fitted A2. У двойного тела прежде
  определить, прогнозируется barycentre или отдельный компонент.

Новая реализация `src/gravity_conventions.py` принимает явные соглашения и
параметры без target ID. Это диагностический force factory; frozen forecast
API и selector не заменены, автоматическое предупреждение ещё не реализовано.

## Воспроизведение и артефакты

Python 3.14.7 через uv, только standard library. Новый открытый raw файл
22,802 bytes, отдельный manifest. Остальные raw, initial states, прежние
численные модули, matrices и scores неизменны. 185 unit tests проходят,
включая проверку солнечной силы через численный градиент потенциала.

```bash
env UV_CACHE_DIR=/private/tmp/astrophysics-ml-uv-cache UV_OFFLINE=1 UV_PYTHON_DOWNLOADS=never uv run --no-project --python-preference only-system --python 3.14.7 python -B src/verify_apophis_gravity_conventions.py
```

`src/run_apophis_gravity_conventions.py` на завершённом наборе читает
checkpoints, сохраняя их содержимое и timestamps. Все результаты локальны
в `outputs/apophis_gravity_conventions/`, исходные данные в
`data/raw/gravity_conventions/`; оба каталога исключены из Git.
Никаких установок, commit или публикации в этой фазе.

Offline verifier независимо пересчитал 77,328 scalar position/velocity
errors, проверил 406,514 accepted endpoints, точное reuse трёх baseline
traces, source/runtime freeze и SHA/size/Git exclusion всех 138 raw файлов
в 14 manifests (157 записей). Число error samples включает повторные
сравнения с разными таблицами и не является числом независимых событий.
Повторно сверены восемь EOBL headers и исходные DE441 constants strings.
Resume генератора и повторный offline verifier прошли без propagation:
SHA-256 и timestamps всех 17 JSON артефактов сохранились. Три предыдущие
матрицы precise RK4, precise DP и development30 relative-force regression
сверены с исходными hashes, изменений нет.
